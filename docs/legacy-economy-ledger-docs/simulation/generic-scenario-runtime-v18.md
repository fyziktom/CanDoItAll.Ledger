# Generic Scenario Runtime v18

The current simulator hardens the generic economic scenario runtime across shared-resource commons, finite productive capacity, market exchange, scenario-pack execution, driver-pack bridges, and WebGL observer evidence. The simulator remains a bounded research and engineering tool; economic claims require headless scenario matrix, invariant, oracle, artifact, and determinism evidence. Browser screenshots are observer evidence only.

## Architecture Boundary

Generic runtime code uses driver registrations, source manifests, scenario packs, bridge adapters, and explicit extension providers. It must not branch on concrete pack folder names or domain words hidden through split strings. Domain vocabulary belongs in scenario packs, fixtures, tests, or scoped extension projects.

`Simulation.MemoryEconomy` now keeps its market mechanism provider separate from sandbox evidence wiring. Sandbox-only probe/oracle extensions live in `Simulation.MemoryEconomy.Sandbox`, which prevents the default generic simulator and Smith registry from carrying memory-economy mechanisms unless an explicit extension owner opts in.

## Scenario Packs And Bridges

Scenario packs remain closed, manifest-hashed bundles owned by the host. The probe runner resolves them through source ids such as shared-resource and finite-capacity sources, not by direct folder-path knowledge in generic execution code.

Driver-pack bridges compare generic autonomous drivers with scenario-pack projections. Shared-resource bridge metrics stay scoped to commons packs, while finite-capacity bridge rows compare productive capacity, land use, demand absorption, concentration, and invariant outcomes against the generic finite-capacity driver.

## Commons And Finite Capacity Models

Commons scenarios model scarce shared pools, participant stock, depletion thresholds, replenishment, restraint, sanctions, and stress cases. Finite-capacity scenarios model scarce productive space, bounded output, external demand, distribution effects, and capacity pressure. Both families use multi-dimensional matrix evidence rather than screenshot-only success.

## WebGL And GLB Contract

Economy-side WebGL bridge code maps visual frames into generic Components WebGL documents. Components receive generic scene/run data and `source.*` provenance metadata; they do not interpret economic claims.

Confirmatory browser evidence requires:

- real Playwright browser capture at `1440x1100` or larger,
- no mobile, small, medium, or narrow evidence artifacts,
- positive GLB network/model diagnostics,
- zero failed GLB requests,
- zero fallback objects,
- phase screenshots for initial, after-apply, mid-run, rule-admin, terminal, and paused-cleanup,
- pose binding evidence for sitting, walking, and working actor variants,
- overhead/status symbol evidence for admin, rule, risk, resource, trade, and production.

## Completed Evidence Gates

Completed validation checks the product matrix and artifact pack, manifest reference resolution, large-screen-only browser evidence, pose/symbol binding reports, determinism replay hashes, and handoff documents. Matrix summaries must use repo-relative artifacts and must not point to local machine paths.
