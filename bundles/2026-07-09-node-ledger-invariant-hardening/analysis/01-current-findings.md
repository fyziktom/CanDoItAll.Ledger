# Current implementation findings

Findings are based on exact source inspection, the 311-test baseline, implementation evidence, and the final 334-test run. `Resolved` means the v1 implementation and proof are complete. `Proposal` and `Open operational` rows remain deliberate roadmap/deployment work and are not hidden as completed work.

| ID | Severity | Status | Finding | Evidence | Treatment |
| --- | --- | --- | --- | --- | --- |
| F-001 | Critical | Resolved | `Mint` previously bypassed asset conservation completely, so unrelated existing token inputs could be duplicated or destroyed. | `AssetConservationValidator.cs`; mint inflation regression | Mint now conserves existing assets while leaving only authorized new-token deltas to policy. |
| F-002 | High | Resolved | Permission delegation previously lacked an aggregate source/supply budget. | `AssetConservationValidator.cs`; permission inflation regression | Permission and rule-token supply cannot increase outside genesis. |
| F-003 | High | Resolved | Canonical hashing previously occurred before cheap resource/shape checks. | `TransactionPreflightValidator.cs`; `LedgerExecutor.cs`; counting-hasher regression | Preflight and shape validation run before canonical hashing. |
| F-004 | High | Resolved | Decimal aggregation could throw overflow instead of returning a deterministic rejection. | `AssetConservationValidator.cs`; overflow regression | Checked accumulation returns `amount_overflow`. |
| F-005 | High | Resolved | Zero-token and completely empty outputs could become UTXOs. | `TransactionShapeValidator.cs`; shape regressions | Token values must be positive and outputs must carry spendable/authority value. |
| F-006 | High | Resolved | BO update/transfer did not preserve carrier token identity. | `BusinessObjectTransitionValidator.cs`; carrier-swap regression | Carrier token ID and unit amount are preserved across versions. |
| F-007 | Medium | Resolved | BO Update could change owner and Transfer could retain the same owner. | `BusinessObjectTransitionValidator.cs`; owner/operation regressions | Update retains owner; Transfer changes owner. |
| F-008 | Medium | Resolved | BO hash binding only ran for inline JSON. | `BusinessObjectTransitionValidator.cs`; external-data hash regression | Any declared transaction data is bound to the changed BO state hash. |
| F-009 | High | Resolved | Custom in-memory validation and append were separate operations. | `InMemoryLedgerStore.cs`; parallel double-spend and token-registration tests | `ILedgerConfirmationStore` serializes decision and append with one async gate. |
